## 3. Course 상태 전환 API 대응 (#454)

### 3.1 타입 정의 수정

```typescript
type CourseStatus = 'DRAFT' | 'READY' | 'REGISTERED';

const COURSE_STATUS_LABELS = {
  DRAFT: '작성중',
  READY: '작성완료',
  REGISTERED: '등록됨'
};

const COURSE_STATUS_COLORS = {
  DRAFT: 'gray',
  READY: 'blue',
  REGISTERED: 'green'
};
```

### 3.2 Curriculum 타입 개선

| 필드 | 용도 |
|------|------|
| `itemId` | 기존 항목 구분용 |
| `learningObjectId` | 읽기 전용, 기존 항목 |
| `contentId` | 선택적, 신규 항목만 필수 |

### 3.3 저장 로직 개선

**핵심 문제 해결**: `learningObjectId`를 `contentId`로 잘못 사용하여 발생하던 에러 수정.

```typescript
// 기존 항목(itemId 있음) 건너뛰기
// 신규 항목(contentId 있음)만 생성
```

### 3.4 UI 상태 처리

| 상태 | 버튼 |
|------|------|
| DRAFT | 작성완료 + 등록 |
| READY | 작성중으로 되돌리기 + 등록 |
| REGISTERED | 수정 불가 |

## 4. 과정 목록 상태별 버튼 렌더링 (#461)

### 4.1 버튼 렌더링 로직

| 상태 | 버튼 | 설명 |
|------|------|------|
| **DRAFT** | "이어서 작성" | 편집 페이지로 이동 |
| **READY** | "상세보기" + "등록하기" | 디테일 페이지 보기 + 직접 등록 |
| **REGISTERED** | "상세보기" | 디테일 페이지 보기 |

### 4.2 handleRegister() 추가

```typescript
const handleRegister = async (courseId: number) => {
  await courseService.register(courseId);
  // 목록 갱신
};
```

## 5. 커리큘럼 데이터 손실 방지 (#467)

### 5.1 문제 상황

과정 등록 중 에러 발생 시 커리큘럼 데이터가 손실되는 문제.

### 5.2 해결 방안

**handleRegister() 함수 개선**

1. **데이터 동기화**: `saveCourse()` 성공 후 서버에서 최신 데이터 재조회
2. **상태 동기화**: `ready()` 성공 시 `courseStatus`를 'READY'로 업데이트
3. **에러 핸들링 개선**: 각 단계별 에러 구분 처리

### 5.3 에러 메시지

| 단계 | 에러 메시지 |
|------|------------|
| 저장 실패 | "저장에 실패했습니다" |
| 작성완료 실패 | "작성완료 처리에 실패했습니다. 저장은 완료되었습니다" |
| 등록 실패 (403) | "등록 권한이 없습니다. OPERATOR 역할이 필요합니다..." |
| 등록 실패 (기타) | "등록에 실패했습니다. 저장은 완료되었으므로 나중에 다시 시도해주세요" |
