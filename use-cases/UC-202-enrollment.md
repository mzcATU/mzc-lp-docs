# UC-202: 수강 신청

## 1. 기본 정보

| 항목 | 내용 |
|------|------|
| Use Case ID | UC-202 |
| Use Case 명 | 수강 신청 |
| Actor | 학습자 (USER) |
| 선행 조건 | - 로그인 상태<br>- 수강 가능한 차수 존재 |
| 후행 조건 | - 수강 신청 완료<br>- 수강 목록에 추가됨 |

## 2. 주요 시나리오 (Main Flow)

### 2.1 자동 승인 방식
```
1. 학습자가 강의 상세 페이지에 접근한다
2. 시스템이 차수 목록을 표시한다
3. 학습자가 원하는 차수를 선택한다
4. 시스템이 차수 상세 정보를 표시한다
   - 일정 (시작일, 종료일)
   - 정원 및 현재 수강 인원
   - 가격 정보
   - 신청 방식
5. 학습자가 "수강 신청" 버튼을 클릭한다
6. [유료 강의인 경우] 시스템이 결제 화면을 표시한다
7. [유료 강의인 경우] 학습자가 결제를 완료한다
8. 시스템이 수강 신청을 처리한다
9. 시스템이 수강 신청 완료 메시지를 표시한다
10. 시스템이 학습자에게 알림을 발송한다
11. 학습자가 "내 강의실로 이동" 버튼을 클릭한다
12. 시스템이 내 강의실 페이지로 이동한다
```

### 2.2 관리자 승인 방식
```
1-6. [Main Flow 1-6과 동일]
7. 시스템이 수강 신청을 "승인 대기" 상태로 저장한다
8. 시스템이 관리자에게 승인 요청 알림을 발송한다
9. 시스템이 학습자에게 승인 대기 메시지를 표시한다
10. [관리자 승인 후] 시스템이 학습자에게 승인 알림을 발송한다
11. 학습자가 내 강의실에서 수강을 시작한다
```

### 2.3 초대 전용 방식
```
1. 관리자가 학습자를 차수에 초대한다
2. 시스템이 학습자에게 초대 알림을 발송한다
3. 학습자가 초대 알림을 확인한다
4. 학습자가 "수락" 버튼을 클릭한다
5. 시스템이 수강을 확정한다
6. 시스템이 내 강의실에 강의를 추가한다
```

## 3. 대안 시나리오 (Alternative Flows)

### A1: 정원 초과
```
6a. 시스템이 정원 초과를 감지한다
    1. 시스템이 "정원이 마감되었습니다" 메시지를 표시한다
    2. 시스템이 대기 신청 옵션을 제공한다 (선택사항)
    3. Use Case 종료
```

### A2: 수강 신청 기간 종료
```
4a. 시스템이 신청 기간 종료를 감지한다
    1. 시스템이 "수강 신청 기간이 종료되었습니다" 메시지를 표시한다
    2. 시스템이 "수강 신청" 버튼을 비활성화한다
    3. Use Case 종료
```

### A3: 중복 신청
```
5a. 시스템이 동일 차수 중복 신청을 감지한다
    1. 시스템이 "이미 수강 신청한 차수입니다" 메시지를 표시한다
    2. 시스템이 "내 강의실로 이동" 버튼을 제공한다
    3. Use Case 종료
```

### A4: 결제 실패
```
7a. 결제가 실패한다
    1. 시스템이 "결제에 실패했습니다" 메시지를 표시한다
    2. 시스템이 결제 재시도 옵션을 제공한다
    3. [재시도 시] Main Flow 7로 돌아간다
    4. [취소 시] Use Case 종료
```

### A5: 선수 과목 미이수
```
5a. 시스템이 선수 과목 미이수를 감지한다
    1. 시스템이 "선수 과목을 먼저 이수해주세요" 메시지를 표시한다
    2. 시스템이 필요한 선수 과목 목록을 표시한다
    3. Use Case 종료
```

## 4. 예외 시나리오 (Exception Flows)

### E1: 네트워크 오류
```
Any step: 네트워크 오류 발생
    1. 시스템이 "네트워크 오류가 발생했습니다" 메시지를 표시한다
    2. 시스템이 재시도 옵션을 제공한다
    3. [재시도 시] 해당 단계로 돌아간다
    4. [취소 시] Use Case 종료
```

### E2: 서버 오류
```
Any step: 서버 오류 발생
    1. 시스템이 "일시적인 오류가 발생했습니다" 메시지를 표시한다
    2. 시스템이 에러를 로깅한다
    3. Use Case 종료
```

## 5. 비즈니스 규칙

### BR-1: 수강 신청 가능 조건
- 수강 신청 기간 내여야 한다
- 정원이 남아있어야 한다 (정원이 설정된 경우)
- 동일 차수에 중복 신청할 수 없다
- 선수 과목이 있는 경우 이수 완료해야 한다

### BR-2: 자동 승인 조건
- `enrollmentType`이 `AUTO`인 경우
- 유료 강의인 경우 결제 완료 필수

### BR-3: 관리자 승인 조건
- `enrollmentType`이 `APPROVAL`인 경우
- 관리자 또는 강사가 승인해야 수강 가능

### BR-4: 초대 전용 조건
- `enrollmentType`이 `INVITE_ONLY`인 경우
- 관리자 또는 강사의 초대 필수
- 공개 수강 신청 불가

### BR-5: 정원 관리
- 정원이 `0`인 경우 무제한
- 정원 초과 시 추가 신청 불가
- 취소 발생 시 정원 자동 복구

### BR-6: 결제 처리
- 유료 강의는 결제 완료 후 수강 가능
- 결제 실패 시 수강 신청 취소
- 환불 정책에 따라 취소/환불 처리

## 6. 데이터 요구사항

### 입력 데이터
```typescript
interface EnrollmentRequest {
  courseTimeId: number;
  paymentInfo?: {
    method: 'CARD' | 'TRANSFER' | 'VIRTUAL_ACCOUNT';
    amount: number;
    // ... 기타 결제 정보
  };
}
```

### 출력 데이터
```typescript
interface EnrollmentResponse {
  enrollmentId: number;
  courseTimeId: number;
  courseName: string;
  status: 'PENDING' | 'APPROVED' | 'REJECTED' | 'COMPLETED';
  enrolledAt: string;
  approvedAt?: string;
  startDate: string;
  endDate: string;
}
```

### 상태 변화
```
신청 → [자동승인] → 승인됨
신청 → [관리자승인 필요] → 승인대기 → [승인] → 승인됨
신청 → [관리자승인 필요] → 승인대기 → [거부] → 거부됨
```

## 7. UI 요구사항

### 7.1 수강 신청 버튼
- 수강 가능한 경우: 파란색 "수강 신청" 버튼
- 정원 마감: 회색 "정원 마감" 버튼 (비활성화)
- 신청 기간 종료: 회색 "신청 마감" 버튼 (비활성화)
- 이미 신청: 초록색 "수강 중" 표시

### 7.2 확인 모달
- 차수 정보 요약
- 가격 정보 (유료인 경우)
- 일정 안내
- 취소 정책 안내
- "신청하기" / "취소" 버튼

### 7.3 결제 화면 (유료인 경우)
- 결제 수단 선택
- 결제 금액 확인
- 약관 동의
- "결제하기" 버튼

### 7.4 완료 화면
- 수강 신청 완료 메시지
- 차수 정보
- "내 강의실로 이동" 버튼
- "계속 탐색하기" 버튼

## 8. API 명세

### 8.1 수강 신청
```http
POST /api/enrollments
Authorization: Bearer {token}
Content-Type: application/json

{
  "courseTimeId": 123,
  "paymentInfo": {
    "method": "CARD",
    "amount": 50000
  }
}

Response 201:
{
  "success": true,
  "data": {
    "enrollmentId": 456,
    "courseTimeId": 123,
    "status": "APPROVED",
    "enrolledAt": "2026-01-22T10:00:00Z"
  }
}

Response 400:
{
  "success": false,
  "error": {
    "code": "ENROLLMENT_FULL",
    "message": "정원이 마감되었습니다"
  }
}
```

### 8.2 수강 신청 승인 (관리자)
```http
PUT /api/enrollments/{enrollmentId}/approve
Authorization: Bearer {token}

Response 200:
{
  "success": true,
  "data": {
    "enrollmentId": 456,
    "status": "APPROVED",
    "approvedAt": "2026-01-22T11:00:00Z"
  }
}
```

### 8.3 수강 신청 취소
```http
DELETE /api/enrollments/{enrollmentId}
Authorization: Bearer {token}

Response 204: No Content
```

## 9. 성능 요구사항
- 수강 신청 처리 시간: 3초 이내
- 동시 신청 처리: 100명 이상
- 정원 관리 동시성 제어: 락(Lock) 사용

## 10. 보안 요구사항
- 인증된 사용자만 수강 신청 가능
- 본인의 수강 신청만 조회/취소 가능
- 결제 정보 암호화 전송
- XSS, CSRF 방지

## 11. 테스트 시나리오

### TC-1: 자동 승인 무료 강의 신청
```
Given: 자동 승인 무료 강의
When: 수강 신청
Then: 즉시 승인됨
```

### TC-2: 관리자 승인 유료 강의 신청
```
Given: 관리자 승인 유료 강의
When: 결제 후 수강 신청
Then: 승인 대기 상태
And: 관리자 승인 시 승인됨
```

### TC-3: 정원 마감
```
Given: 정원 10명, 현재 10명 수강 중
When: 11번째 학습자 신청 시도
Then: "정원 마감" 에러
```

### TC-4: 중복 신청 방지
```
Given: 이미 신청한 차수
When: 동일 차수 재신청 시도
Then: "이미 신청됨" 에러
```

### TC-5: 결제 실패 처리
```
Given: 유료 강의
When: 결제 실패
Then: 수강 신청 취소
And: 에러 메시지 표시
```
